# بروتوكول تقييم دقة الإجابات (مخرج مهندس LLM & RAG)

## الهدف
قياس جودة المساعد الزراعي بشكل قابل للتكرار، ومقارنته بمستهدفات المشروع: **زمن الاستجابة ≤ 3 ثوانٍ**، وإجابات مبنية على الأدلة المعتمدة فقط، ورفض الأسئلة خارج النطاق.

## مجموعة الاختبار الذهبية (`data/eval/golden_set.jsonl`)
كل سطر: سؤال بلهجة مزارع، المحصول (اختياري)، الملفات المتوقع استرجاعها، كلمات مفتاحية متوقعة في الإجابة، وهل السؤال داخل النطاق.
- **الحد الأدنى للتسليم: 50 سؤالًا**، منها 10 خارج النطاق على الأقل، وتغطي الأمراض الخمسة المستهدفة والري والتسميد والتربة.
- يكتب الأسئلة ويراجع الإجابات المرجعية **محلل الأعمال/مهندس زراعي**، لا مطوّر النظام (لتفادي التحيز).
- تُضاف أسئلة بصياغات مختلفة من محافظات مختلفة (قاموس اللهجات).

## المقاييس
| الفئة | المقياس | المستهدف المقترح |
|---|---|---|
| الاسترجاع | Hit@3 / MRR | ≥ 0.90 / ≥ 0.80 |
| الإجابة | Keyword recall | ≥ 0.85 |
| الإجابة | نسبة الإجابات المقرونة بمصدر [n] | ≥ 0.95 |
| الأمان | رفض الأسئلة خارج النطاق | ≥ 0.95 |
| الإخلاص | LLM-judge Faithfulness (1–5) | ≥ 4.5 |
| الأداء | TTFT p95 | ≤ 3000 ms |

## خطوات التنفيذ
1. `make eval-retrieval` — بدون مفتاح API؛ يعطي Hit@k وMRR **وقيمة `min_similarity` المقترحة**. ضعها في `.env`.
2. `make eval` — تقييم شامل مع LLM-judge. التقرير في `reports/eval_report.md`.
3. **مراجعة بشرية**: مهندس زراعي يراجع عينة (≥ 20%) من الإجابات ويصنفها: صحيحة / صحيحة جزئيًا / خاطئة / خطرة. أي إجابة "خطرة" (جرعة أو مبيد غير مذكور في المصدر) تُعتبر فشلًا حرجًا.
4. تُعاد الدورة بعد كل تغيير في: قاعدة المعرفة، الـ chunking، الـ prompt، أو النموذج.

## ملاحظات منهجية
- الـ LLM-judge مساعد للفرز فقط، وليس بديلًا عن المراجعة البشرية.
- تسجَّل نتيجة كل تشغيل (`reports/`) للمقارنة بين الإصدارات.
